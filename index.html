Public repo2026 · Personal project

FixAgent: an AI agent that fixes bugs

Give it a repository and a bug report or GitHub issue. It explores the code, runs the tests, edits the source and hands back a patch or pull request. A fix only counts if the tests fail before and pass after. Works on Python, C++ and Rust code, with a React dashboard to watch it work.

How it is built and tested
  • Agent loop, tools and LLM client in plain Python, talking to any OpenAI-style tool-calling endpoint.
  • Safety rules: works on a copy, test files are read-only, commands run from an allowlist with a timeout, and the model's own claim of success is ignored.
  • A fast code-search CLI in Rust and a React/TypeScript dashboard.
  • 68 offline tests with a scripted model run in GitHub Actions. Not yet run with a real model or on a public benchmark.

Public repo2026 · MSc group project

AutoSPECTRA: CAN bus intrusion detection

Deep learning to detect DoS, fuzzing, gear and RPM spoofing attacks on a vehicle CAN bus, using the public HCRL Car-Hacking dataset, with automated incident reporting.

My part and how it was tested
  • I designed and own the evaluation harness.
  • Time-ordered train/test splits with automated leakage checks, because neighbouring CAN frames look alike and random splits can leak.
  • Reported per-class precision, recall, F1, ROC-AUC, false-positive rate and detection latency.
  • Baseline, CNN and sequence models compared on identical splits, with window-size ablations.

How I work

Four habits I bring to every model

Split by time, not by luck

When data arrives in order, I test on later data than I train on, so the score reflects what happens after deployment.

Check for leakage first

I automate the checks that catch duplicate and overlapping records before trusting any number.

Start with a baseline

A deep model has to beat a simple one on the same split to earn its complexity.

Say what it can't do

Each README lists its limits. If a result needs a caveat, the caveat goes next to the result.
